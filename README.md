# Secure Coding Lab

初心者が「脆弱性の意味を読む → 通常操作と攻撃入力を試す → PHPを直す → 同じ操作で修正を確かめる」と進める研修アプリです。教材・コードエディタ・実行画面を並べます。PHPとSQLiteを実際に実行し、画面上だけの模擬判定は行いません。

![教材・エディタ・実行画面](docs/workspace.png)

## 10〜20人の研修として提供する

全員が同じURLへアクセスし、各自の受講コードで専用の学習環境へ入ります。受講者ごとにPHP実行コンテナ、保存コード、DB、学習済み記録を分けます。端末側のインストールは不要です。

[同時受講環境の起動・受講コード配布・停止方法](docs/classroom.md)を参照してください。社内LANやVPNからアクセスするLinuxサーバーを使います。

```sh
# 実際のサーバーのIPへ置き換える
python3 scripts/classroom.py --seats 20 --host 192.168.1.50 --bind 0.0.0.0
docker compose -f .classroom/compose.json up --build -d --wait
```

講師が `.classroom/roster.csv` の各自の受講コードを配り、全員が `http://192.168.1.50:8080` を開きます。HTTPによるLAN・VPN内の利用を想定した設定です。一般公開する場合はHTTPSと入口のアクセス制限を追加する必要があります。20人分の環境を起動し、同時ログインと200回の保存・実行・DB照合を検証しました。提供先での性能は、そのサーバーで事前に確認してください。

## 1人でローカル起動する

Docker Engine / Docker DesktopとDocker Compose v2が必要です。初回ビルドにはインターネット接続を使います。

```sh
git clone https://github.com/ryuchan00/secure-coding-lab.git
cd secure-coding-lab
docker compose up --build -d --wait
```

[http://localhost:8080](http://localhost:8080) を開きます。個人用は8080〜8087番ポートを使用します。Node.jsやPHPをホストへインストールする必要はありません。個人用の起動設定を複数人で共有すると同じコードを編集するため、研修には上の同時受講設定を使ってください。

## 教材

全教材に、用語・本来の動作・脆弱性の意味・成立する理由・対策・確認方法の解説と、体験／修正の手順があります。最初に解説を表示し、手順は別のタブで読みます。「はじめての方へ」には画面の使い方とPHP・HTML・JavaScriptの説明があります。コードを書き慣れていない場合は修正例を反映し、変化を確かめられます。

| 教材 | 体験 | 修正 | 目安 |
| --- | --- | --- | --- |
| SQLインジェクション | SQLiteへのSQLが変わり、パスワード確認を回避 | PDOのプリペアドステートメント | 15分 |
| 反射型XSS | 入力したJavaScriptがブラウザで動く | HTML本文への出力時にエスケープ | 15分 |
| CSRF | 別オリジンのページから送金される | セッション固有トークンの検証 | 20分 |
| アクセス制御の不備 | 番号を変えて他人の明細を読む | ログイン中の利用者と所有者の照合 | 15分 |
| 保存型XSS | DBに保存した攻撃入力が再読込でも動く | 保存されたコメントの出力時にエスケープ | 20分 |
| ディレクトリトラバーサル | 公開フォルダーの外の架空ファイルを読む | 公開するファイルの許可リスト | 15分 |

SQLi教材ではSQLiteの会員DB、保存型XSS教材ではコメントDBを使います。教材で使う個人情報・ファイル内容は架空です。SQLi教材では仕組みに集中するためパスワードを平文保存しています。実際の認証ではハッシュ化と`password_verify`なども必要です。修正例はその演習で扱う脆弱性への対策であり、実サービスの完成形ではありません。

CSRFの口座と攻撃ページは同じホストの異なるポートです。別オリジンですが同一サイトなので、`SameSite=Lax`でもCookieが送られます。この状況でCSRFトークンが送金を防ぐことを確認します。

## 徳丸本・CureVulnとの関係

[徳丸本第2版の公式目次](https://machida.kanagawa.jp/content.html)にあるように、書籍はXSS・SQLi・CSRFに加え、ファイルアクセス、認証・認可、セッション管理なども扱います。このアプリの6教材で全範囲を網羅しているわけではありません。コードと解説は本プロジェクトで作成し、書籍の本文・図・サンプルコードを転載していません。

[2017年度未踏事業のCureVuln紹介資料](https://www.ipa.go.jp/archive/files/000065633.pdf)にある学習形式を参考にしています。[元の公開教材](https://github.com/curevuln/curevuln-exercise)は調査しましたが、リポジトリ全体のライセンスを確認できなかったため転載していません。CureVuln本体のフォークや公式後継ではありません。本プロジェクトの実装と教材はMITライセンスです。

## 操作と保存

中央のPHPを編集し、「保存して Run」またはCtrl / Command + Enterで反映します。Tabはインデント追加、Shift + Tabは解除です。CodeMirror 5を同梱し、PHPの色分けと行番号を表示します。編集中の外部CDN接続はありません。PHPのOPcacheを無効にし、保存後のリクエストで編集内容を実行します。

保存コードと学習済み記録はDockerボリュームに置きます。「学習済み」は自己確認の記録で、自動採点ではありません。DB・セッション・コメントはPHPコンテナの一時領域に置きます。未保存のコードは教材切替・画面離脱時に確認します。

```sh
# 個人用を停止。保存コードと学習済み記録は残る
docker compose down
# 個人用のDB・コメント・口座残高を初期化
docker compose restart sqli xss csrf access stored-xss traversal
# 個人用の保存データもすべて削除して開始
docker compose down -v
docker compose up -d --wait
```

「初期コードに戻す」は選択した教材のコードだけを戻します。構文エラーは実行画面に表示されます。反応しない場合は該当するPHPコンテナをrestartしてください。WSLではDocker DesktopのWSL連携を有効にします。

## 実行環境と検証

PHPは非root・読み取り専用ルートファイルシステムで実行し、メモリ・CPU・プロセス数を制限します。ネットワークはinternalとし、HTTPはnginxゲートウェイを介します。Dockerソケットやホストのホームディレクトリは渡しません。編集APIではHostとOriginを確認し、エディタとPHP画面は別オリジンにします。同時受講用では入口の認証と受講者ごとのネットワーク・実行環境の分離も行います。

意図的に脆弱なPHPを実行するため、匿名の一般利用者向けコード実行サービスとしての隔離強度は保証していません。講師が受講コードを配布した研修参加者を対象に使用してください。

```sh
npm ci
npx playwright install --with-deps chromium
docker compose up --build -d --wait
npm test
```

Playwrightは6教材の攻撃成立、修正後の拒否、通常操作を確認します。[同時受講用のテスト](docs/classroom.md#2人での分離テスト)では2人のブラウザで同時編集、DB・進捗・残高の分離、未認証リクエストの拒否を確認します。テストは教材コードとデータを変更するため、受講中の環境では実行しないでください。

| パス | 内容 |
| --- | --- |
| `app/` | 編集API、初心者向け画面、受講入口、CSRF攻撃ページ |
| `lessons/` | 解説・初期コード・修正例 |
| `runtime/` | PHP実行環境とゲートウェイ |
| `scripts/classroom.py` | 同時受講設定と受講コードの生成 |
| `tests/` | ブラウザでの攻撃・対策・分離の検証 |
